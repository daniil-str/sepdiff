# SEPDiff — история изменений статей Stanford Encyclopedia of Philosophy

Цель: для любой статьи SEP показать «историю коммитов» — список версий, что
изменилось между ними, и построчный/пословный diff. Аналог wiki history + `git log`.

Стек: Python (FastAPI + Jinja2) на бэке, htmx + чистый CSS на фронте, SQLite как
хранилище. Без сборки фронта, без Node, без Celery/Redis.

---

## 1. Источник данных (проверено 2026-09-09)

### 1.1 Что есть у SEP

SEP выпускает **фиксированные архивные издания** 4 раза в год — 21 марта (spr),
21 июня (sum), 21 сентября (fall), 21 декабря (win). Каждое издание — это
неизменяемый снимок всей энциклопедии.

- Список изданий: `https://plato.stanford.edu/archives/`
  На сегодня **116 изданий**, самое старое — `fall1997`, самое свежее — `sum2026`.
- Слаг издания: `spr|sum|fall|win` + год, напр. `win2023`.
- Оглавление издания: `https://plato.stanford.edu/archives/<edition>/contents.html`
  (ссылки на статьи вида `entries/<slug>/`).
- Архивная статья: `https://plato.stanford.edu/archives/<edition>/entries/<slug>/`
- Живая (текущая, между изданиями меняется) версия:
  `https://plato.stanford.edu/entries/<slug>/`

**Ключевой факт для архитектуры: архивные издания иммутабельны.** Скачали один
раз — кешируем навсегда, никогда не перезапрашиваем. Обновлять надо только
живую версию и последнее издание.

### 1.2 Дата ревизии внутри страницы

На каждой странице есть строка вида:

> First published Thu May 20, 2010; substantive revision Tue Jul 28, 2020

Её одной **недостаточно**, чтобы найти изменение: «minor correction» эту дату
не двигает. Зато, как показал спайк (§13), **смена этой даты — это ровно флаг
substantive у SEP**. До 2007 года `#pubinfo` нет, но дата есть в другой форме
(спайк, прогон 2):

| эпоха вёрстки | где дата | пример |
|---|---|---|
| 2007+ | `#pubinfo` | `substantive revision Tue Jul 28, 2020` (или `First published …`) |
| 2003–2006 | плашка в шапке | `last substantive content change JUN 6 2003` |
| ~2002 | плашка в шапке | `content revised NOV 2 1997` |
| 1996–2001 | подвал | `Content last modified: September 8, 1997` |

Одно и то же событие в разных форматах может расходиться на день
(`Dec 5, 2000` в подвале → `DEC 6 2000` в плашке), поэтому даты из разных
форматов считаются равными при разнице ≤ 1 дня. Итоговое правило:

| условие (по порядку) | вердикт |
|---|---|
| сырой HTML совпал | `identical` (на практике не встречается, см. §13) |
| обе даты известны и различаются | `substantive` (даже если текст тот же) |
| текст совпал, но изменились ссылки или разбиение на блоки | `minor` |
| текст, ссылки и разбиение совпали | `markup_only` |
| текст изменился, дата известна и та же | `minor` |
| текст изменился, даты нет | `changed` (вид правки не определить) |

Источник истины о факте изменения — **хеши нормализованного текста**
(статья + отдельно раздел со ссылками + разбиение на блоки), дата отвечает
только на вопрос «substantive или minor».

### 1.3 archinfo.cgi — эталон, но не для краулинга

`https://plato.stanford.edu/cgi-bin/encyclopedia/archinfo.cgi?entry=<slug>`
отдаёт готовый список версий статьи с пометками «substantive content change» /
«minor correction». Это ровно то, что мы хотим построить.

**Но `robots.txt` запрещает `/cgi-bin/`.** Автоматически ходить туда нельзя.
Используем эту страницу иначе: вручную снимаем её для ~10 статей и кладём в
`tests/fixtures/` как **ground truth** для проверки собственного детектора
изменений. Это лучший из доступных тестов на корректность.

### 1.4 Что говорит robots.txt

Разобрано целиком. Существенное:

- `crawl-delay: 5` — **пять секунд между запросами**, это жёсткое ограничение
  и оно определяет весь UX (см. §4).
- Запрещены: `/cgi-bin/`, `/diffs/`, `/search/`, `/rss/`, `/perl/`, статика.
- Запрещены **все регистровые варианты** `/archives/` (`/Archives/`, `/ARCHIVES/`,
  … ~250 строк) — **кроме канонического строчного `/archives/`**. То есть
  каноничный путь к архивам разрешён явно и намеренно.
- `User-Agent: ia_archiver` → `Disallow: /` — SEP не приветствует внешнее
  зеркалирование. Wayback Machine как источник рассматривать не будем
  (и по духу robots, и потому что квартальные издания дают достаточную
  гранулярность).

### 1.5 Правовое / этичное

Тексты SEP защищены копирайтом (каждая статья — © автора). Локальный
инструмент для чтения истории — нормально. **Не публиковать зеркало текстов**
в открытом вебе. Если когда-нибудь захочется выложить — выкладывать только
метаданные (какие издания менялись, объём diff), без тела статей.

Принцип: **ядро (fetch/extract/diff) не знает про веб**. CLI и FastAPI —
две тонкие обёртки над `service.py`. Это позволяет закончить и отладить
полезный инструмент до того, как написана хоть одна строчка UI.

### 2.1 Зависимости

- `httpx` — HTTP-клиент (async).
- `selectolax` — быстрый HTML-парсер (lexbor). Альтернатива: `lxml`.
  `beautifulsoup4` не нужен, но пригодится как запасной вариант для «кривого»
  HTML изданий 1997–2003.
- `fastapi` + `uvicorn` + `jinja2`.
- `typer` — CLI.
- Стандартная библиотека: `sqlite3`, `difflib`, `hashlib`, `gzip`, `re`,
  `unicodedata`.
- Dev: `pytest`, `ruff`.

Никакой ORM: запросов мало, схема простая, сырой `sqlite3` быстрее пишется и
меньше весит. Менеджер пакетов — `uv`.

> Окружение: Python 3.13.15 и uv 0.12.11 установлены через winget
> (user scope); проект инициализирован `uv init --package`.

## 3. Схема данных

```sql
-- 116 квартальных изданий
CREATE TABLE editions (
    slug        TEXT PRIMARY KEY,   -- 'win2023'
    season      TEXT NOT NULL,      -- spr|sum|fall|win
    year        INTEGER NOT NULL,
    released_on DATE NOT NULL,      -- 1997-09-21 …
    ordinal     INTEGER NOT NULL    -- 0..N, порядок по времени
);

CREATE TABLE entries (
    slug            TEXT PRIMARY KEY,   -- 'kant'
    title           TEXT,
    authors         TEXT,
    first_published DATE,
    scan_state      TEXT NOT NULL DEFAULT 'new',  -- new|partial|complete
    last_scanned_at TIMESTAMP
);

-- один снимок статьи в одном издании
CREATE TABLE snapshots (
    entry_slug    TEXT NOT NULL REFERENCES entries(slug),
    edition_slug  TEXT NOT NULL REFERENCES editions(slug),
    http_status   INTEGER NOT NULL,   -- 200 | 404 (статьи ещё/уже нет)
    blob_sha      TEXT,               -- путь в data/blobs, сырой gzip HTML
    raw_sha       TEXT,               -- хеш сырого HTML
    text_sha      TEXT,               -- хеш нормализованного текста ← главный
    body_sha      TEXT,               -- хеш текста без библиографии
    biblio_sha    TEXT,
    apparatus_sha TEXT,               -- Other Internet Resources + Related Entries (§5.1)
    struct_sha    TEXT,               -- последовательность типов блоков (p, li, …) без текста
    revision_date DATE,               -- дата последней существенной правки (§1.2)
    date_source   TEXT,               -- pubinfo | header-substantive | header-revised | footer
    word_count    INTEGER,
    extractor     TEXT,               -- какой экстрактор сработал (era-1997 …)
    suspect       INTEGER DEFAULT 0,  -- не прошёл санити-чек
    fetched_at    TIMESTAMP NOT NULL,
    PRIMARY KEY (entry_slug, edition_slug)
);

-- вычисляемая «история коммитов»: только издания, где что-то изменилось
CREATE TABLE revisions (
    entry_slug   TEXT NOT NULL,
    edition_slug TEXT NOT NULL,       -- издание, В КОТОРОМ появилось изменение
    prev_edition TEXT,                -- предыдущее издание с контентом
    kind         TEXT NOT NULL,       -- created|substantive|minor|changed|markup_only|removed
    words_added      INTEGER,
    words_removed    INTEGER,
    blocks_changed   INTEGER,
    sections_touched TEXT,            -- JSON-список заголовков
    PRIMARY KEY (entry_slug, edition_slug)
);

CREATE TABLE jobs (
    id          INTEGER PRIMARY KEY,
    kind        TEXT NOT NULL,        -- scan_entry | refresh_live | seed_index
    target      TEXT NOT NULL,
    state       TEXT NOT NULL,        -- queued|running|done|error
    done_units  INTEGER DEFAULT 0,
    total_units INTEGER,
    message     TEXT,
    created_at  TIMESTAMP,
    updated_at  TIMESTAMP
);
```

Сырой HTML хранится **content-addressed**: `data/blobs/<sha[:2]>/<sha>.html.gz`.
Одинаковые снимки (статья не менялась 5 изданий подряд) занимают место один раз.

## 4. Краулер и главное ограничение UX

`crawl-delay: 5` × 116 изданий = **~10 минут на полное сканирование одной статьи**.
Это не «нажал и увидел» — это фоновая задача. Архитектура должна это принять
честно, а не бороться с этим.

### 4.1 Правила вежливости

- Один воркер, глобальный семафор — **не более 1 запроса в 5 секунд** на весь
  процесс, независимо от числа пользователей.
- `User-Agent` с контактом: `SEPDiff/0.1 (+https://github.com/<you>/sepdiff; <email>)`.
- Уважать `Retry-After`, экспоненциальный backoff на 5xx, максимум 3 ретрая.
- Никогда не трогать `/cgi-bin/`, `/diffs/`, `/search/`.
- Кеш архивных изданий — **навсегда**. Повторный запрос уже скачанного
  `(entry, edition)` не делается никогда.
- Живая версия — не чаще раза в сутки, с `If-None-Match` / `If-Modified-Since`.
- Прокси — через стандартные `HTTPS_PROXY` / `HTTP_PROXY` (httpx читает их сам).
  С машины разработки Stanford напрямую недоступен, работает только через
  локальный прокси (§13).
- Fail-fast: connect timeout 10 с, после 2 сетевых ошибок подряд — стоп,
  а не зависание на каждом из 116 изданий.

### 4.2 Двухфазное сканирование (решает проблему ожидания)

**Фаза A — «грубый проход»** (~15–20 запросов, ~1.5 минуты):
берём каждое 6–8-е издание (примерно раз в 2 года) плюс первое и последнее.
Даёт пользователю читаемый скелет истории почти сразу.

**Фаза B — «уточнение»**: для каждой пары соседних отобранных изданий, где
`text_sha` различаются, догружаем издания между ними (бинарным делением или
подряд — их всего 5–7). Пары с одинаковыми хешами **не догружаем сразу**,
но помечаем интервал как `assumed_unchanged`.

> Честное предупреждение: равенство хешей на концах интервала не доказывает
> отсутствия изменений внутри (правка и откат). Поэтому:
> - в UI такие интервалы помечаются серым «не проверено»;
> - есть кнопка **Deep scan** (все 116 изданий подряд), которая доводит статью
>   до `scan_state='complete'`.
>
> Для статьи, которую пользователь реально изучает, deep scan — правильный
> дефолт; двухфазность нужна только чтобы было что показать в первые 90 секунд.

### 4.3 Очередь задач

Никакого Celery. Таблица `jobs` + один `asyncio.Task`, стартующий в
`lifespan` приложения FastAPI. Одна БД, один процесс, `uvicorn` без воркеров
(или с одним). Прогресс пишется в `jobs.done_units` — фронт его поллит.

Тот же воркер переиспользуется CLI-командой `sepdiff fetch <slug>`.

## 5. Извлечение текста — самая трудоёмкая часть

Это то, где реально уйдёт время. Diff — решённая задача, `difflib` из коробки;
а вот «получить из HTML 1998 года и HTML 2026 года сравнимые тексты» — нет.

### 5.1 Что выбрасываем, а что храним отдельно

**Выбрасываем**: навигацию (Browse / About / Support SEP), «Friends PDF
Preview», «Author and Citation Info», Academic Tools, футер с копирайтом,
конфиг MathJax, скрипты/стили. Всё это генерирует сайт, а не автор; оно
меняется при каждом редизайне и дало бы ложные «изменения» во всех статьях сразу.

**Храним отдельным потоком `apparatus`** (свой хеш, свой diff):
Other Internet Resources и Related Entries. В текст статьи они не входят, но
правки в них SEP считает «minor correction»: у `kant` `fall2020 → fall2023`
изменились **только** они (§13). Если их выбрасывать, такие ревизии
становятся невидимыми.

### 5.2 Что оставляем и как структурируем

Извлекаем в промежуточное представление — список блоков:

```python
@dataclass
class Block:
    kind: str      # heading | para | listitem | blockquote | bibitem | formula
    level: int     # для heading
    section: str   # ближайший вышестоящий заголовок (для «какие разделы затронуты»)
    text: str      # нормализованный текст
    html: str      # исходный HTML блока — для рендера diff с курсивом/ссылками
```

Библиография отделяется в свою последовательность блоков: правки в списке
литературы происходят постоянно и, будучи смешаны с телом, зашумляют diff.

### 5.3 Нормализация (`normalize.py`)

- Unicode NFC; типографские кавычки/тире → ASCII-эквиваленты; `&nbsp;` → пробел.
- Схлопывание пробелов, обрезка краёв.
- Выбрасывание автогенерируемых `id`/`name` у якорей и номеров сносок.
- Приведение записи математики (у SEP она мигрировала GIF → HTML-entities →
  MathJax/LaTeX за 28 лет — отдельный источник ложных диффов; на первом
  этапе просто заменять формулы на плейсхолдер `⟨math⟩` и не сравнивать их).

Хеши считаем от нормализованного текста → `text_sha`. От сырого HTML →
`raw_sha`. Если `raw_sha` изменился, а `text_sha` нет — это `markup_only`,
и в истории такая «ревизия» показывается свёрнутой/приглушённой. **Эта
пара хешей — то, что отличает полезный инструмент от шумного.**

### 5.4 Разные эпохи вёрстки

Цепочка экстракторов, пробуем по порядку, первый сработавший выигрывает:

1. `modern` — современная разметка (контейнер основного текста; точные
   `id`/классы уточнить на живом образце, исторически `#main-text` / `#aueditable`).
2. `mid` — издания ~2003–2010.
3. `legacy` — 1997–2002, много `<table>`-вёрстки и голых `<p>`.
4. `fallback` — эвристика: берём самый «текстоёмкий» узел (Readability-подобная
   оценка), логируем в `snapshots.extractor`, чтобы видеть, где сработал
   запасной путь.

Каждый экстрактор возвращает `None`, если не уверен (нет заголовка,
подозрительно мало текста, нет строки «First published»). Санити-чек:
если у соседних изданий объём текста скачет более чем в 2 раза — это,
скорее всего, ошибка экстрактора, а не правка автора; помечаем снимок
`suspect` и не строим по нему ревизию.

Фикстуры: сохранить по одной статье из ~8 разных эпох в `tests/fixtures/`
и держать на них regression-тесты.

## 6. Diff

### 6.1 Двухуровневый алгоритм

1. **Блочный**: сравниваем последовательности хешей блоков через
   `difflib.SequenceMatcher(a=[hash(b.text) for b in A], b=[...])`.
   Получаем opcodes: `equal | replace | delete | insert`.
2. **Пословный**: внутри каждого `replace` сопоставляем абзацы по схожести
   (`SequenceMatcher.ratio() > 0.5` → «изменённый», иначе «удалён + добавлен»),
   и внутри пары считаем diff по словам, склеивая соседние операции
   в `<ins>` / `<del>`.
3. Неизменённые участки сворачиваются, показывается ±1 блок контекста
   и плашка «показать N неизменённых абзацев».

### 6.2 Сводка (шапка diff)

`+312 / −87 слов`, `4 раздела затронуто`, чипы с названиями разделов,
отдельная строка «библиография: +3 источника». Плюс пометка
`substantive` / `minor` / `markup only`, выведенная из наших хешей.

### 6.3 Позже (фаза 3+)

- Детекция перемещённых блоков (абзац переехал в другой раздел) — сравнение
  множеств хешей до применения `SequenceMatcher`.
- Diff по разделам («что стало с §3 за 10 лет»).

## 7. Веб-интерфейс (FastAPI + Jinja2 + htmx)

Никакого JS кроме `htmx.min.js` (вендорить в `static/`, не CDN — офлайн-работа).
Один `base.html`, остальное — фрагменты, возвращаемые как куски HTML.
Каждая страница работает и без htmx, полной перезагрузкой; htmx только
подменяет фрагменты.

### 7.1 Маршруты

| Метод | Путь | Отдаёт |
|---|---|---|
| GET | `/` | поиск |
| GET | `/search?q=` | **фрагмент**: список статей (`hx-trigger="keyup changed delay:300ms"`) |
| GET | `/e/{slug}` | страница истории статьи |
| GET | `/e/{slug}/history` | **фрагмент**: таблица ревизий |
| POST | `/e/{slug}/scan` | ставит задачу в очередь, отдаёт фрагмент прогресса |
| GET | `/jobs/{id}/progress` | **фрагмент**: полоса прогресса (`hx-trigger="every 2s"`) |
| GET | `/e/{slug}/diff?a=&b=` | страница diff |
| GET | `/e/{slug}/diff/pane?a=&b=` | **фрагмент**: сам diff (смена версий в селектах) |

### 7.2 Экран истории — «git log»

Таблица, новые сверху:

```
● Fall 2024   substantive   +1240 / −310   §2, §4, Bibliography   [diff с пред.]
○ Fall 2023   minor         +18 / −6       §3                     [diff]
· Spr 2023    markup only                                          (приглушено)
┆ (7 изданий без изменений)
● Fall 2020   substantive   +4100 / −900   …
◇ Sum 2010    created       первое издание
```

Слева — чекбоксы «сравнить произвольные две версии» (как в MediaWiki):
выбрал два — кнопка «Сравнить» становится активной.

Если статья ещё не сканирована — вместо таблицы кнопка «Построить историю»,
после нажатия — полоса прогресса, поллящая `/jobs/{id}/progress` раз в 2 с;
по завершении сервер отдаёт `HX-Trigger`, который перезагружает таблицу.
(SSE тоже возможен, но поллинг проще и здесь дешевле некуда.)

### 7.3 Экран diff

Два `<select>` с изданиями, `hx-get` на `/diff/pane`, `hx-target` на панель.
Переключатель «рядом / построчно». CSS: `ins {background:#d5f5d5}`,
`del {background:#ffd7d5; text-decoration:line-through}` — плюс тёмная тема
через `prefers-color-scheme`.

## 9. Экспорт в настоящий git (фаза 4, но идея важная)

Раз метафора — git, можно материализовать её буквально: `sepdiff export-git`
создаёт репозиторий, где каждое издание с изменением = коммит
(`author` = автор статьи, `date` = дата выхода издания, сообщение =
`fall2020: substantive revision`), а содержимое — извлечённый текст,
разбитый по разделам на файлы.

Плюсы: бесплатно получаем `git log`, `git blame` («когда появился этот абзац»),
`git diff --color-words`, детекцию перемещений, просмотр в любом привычном
инструменте. Это не замена веб-UI, а дополнение — и очень дешёвое, раз
извлечение текста уже написано.

## 11. Риски и открытые вопросы

1. **Скорость краулинга.** 5 с/запрос — неустранимо. Смягчается иммутабельным
   кешем (второй раз статья открывается мгновенно) и двухфазным сканированием.
   Не пытаться обходить: параллелить запросы к plato.stanford.edu нельзя.
2. **Гниение старой вёрстки.** Основной источник багов. Митигация — фикстуры
   по эпохам, поле `extractor` в снимке, санити-чек по объёму текста.
3. **Формулы и спецсимволы.** У SEP несколько поколений представления
   математики; на первом этапе — плейсхолдеры, иначе получим ложные правки
   в каждой логической статье.
4. **Переименования слагов и редиректы.** Статья может сменить slug или
   быть слита с другой. Ловить 301 и вести таблицу алиасов (фаза 3).
5. **Отсутствие статьи в старых изданиях.** 404 — это не ошибка, а факт
   («ещё не опубликована» / «удалена»); хранить как `http_status=404`
   и не ретраить.
6. **Проверка корректности.** Единственный доступный эталон — archinfo.cgi,
   и ходить туда автоматически нельзя. Снять руками 10 страниц в фикстуры
   и на них верифицировать классификатор substantive/minor.
7. **Копирайт.** Инструмент — локальный. Публично — только метаданные.

### Прогон 1: `kant` (2026-09-10)

Данные: `kant` × 6 изданий. Итог: **5 из 5 совпадений с archinfo.cgi**, анализ
6 изданий занимает < 0.5 с. Подход рабочий.

| пара | наш вердикт | archinfo | +слов / −слов | блоков | ссылки |
|---|---|---|---|---|---|
| sum2010 → spr2016 | substantive | substantive ✅ | +110 / −12 | 7 | 0 |
| spr2016 → fall2020 | substantive | substantive ✅ | +65 / −77 | 32 | 5 |
| fall2020 → fall2023 | minor | minor ✅ | 0 / 0 | 0 | 1 |
| fall2023 → win2023 | markup_only | без изменений ✅ | 0 / 0 | 0 | 0 |
| win2023 → fall2024 | substantive | substantive ✅ | +174 / −10 | 6 | 0 |

### Что узнали

1. **Дата «substantive revision» — это ровно флаг substantive у SEP.**
   Правило классификации — в §1.2.
2. **Minor correction может вообще не трогать текст статьи.** У `kant`
   `fall2020 → fall2023` добавилась одна Related Entry и починились URL в
   Other Internet Resources, больше ничего. Отсюда отдельный поток
   `apparatus` (§5.1, §3). Без него был 1 провал из 5.
3. **`identical` на практике не бывает.** Между изданиями всегда меняется
   шаблон: название издания, `role="menuitem"`, `alt` у логотипа, футер
   (CSLI → Department of Philosophy), иногда даже запечённая в архив
   SSI-ошибка `[an error occurred while processing the directive]`. `raw_sha`
   почти бесполезен; нормальное состояние «без изменений» — `markup_only`.
4. **SEP переразбивает строки исходника между изданиями**: тот же текст,
   другие переносы. Нормализация пробелов обязательна.
5. **Вёрстка.** В изданиях 2016+ контейнеры `#preamble`, `#main-text`,
   `#bibliography`, `#other-internet-resources`, `#related-entries` оказались
   ровно такими, как ожидалось. В `sum2010` вёрстка старая: всё лежит в
   `#aueditable`, разделы размечены только `<h2>`, оглавление — голый `<ul>`
   из якорных ссылок. Экстрактор `aueditable` с сегментацией по заголовкам
   даёт те же 142–143 блока, что и современный. До этой починки пара
   `sum2010 → spr2016` показывала ложные −1 842 слова (библиография в теле).
6. **Сеть.** С машины разработки Stanford напрямую недоступен (DNS резолвится,
   TCP — таймаут; при этом pypi.org отвечает). Через локальный прокси
   (`HTTPS_PROXY=http://127.0.0.1:2080`) всё работает.
7. **Diff читается.** Реальные правки видны пословно: `capitol → capital`,
   `1780's → 1780s`, снятые кавычки у цитат. Неизменённое свёрнуто.

### Прогон 2: четыре статьи, издания 1997–2025 (2026-09-11)

Статьи подобраны под непроверенное: `qualia` (с fall1997, все эпохи вёрстки),
`logic-paraconsistent` (с fall1997, формулы), `logic-modal` (формулы и 8
minor-правок подряд). 40 снимков, эталоны сняты с archinfo вручную.

| статья | снимков | пар | совпало с archinfo |
|---|---|---|---|
| kant | 6 | 5 | 5 ✅ |
| qualia | 10 | 9 | 8 (1 — см. п. 5 ниже) |
| logic-paraconsistent | 9 | 8 | 8 ✅ |
| logic-modal | 15 | 14 | 14 ✅ |
| **итого** | **40** | **36** | **35** |

Анализ 40 снимков — ~2 с. Первый прогон на новых статьях дал 7 провалов из
31; все, кроме одного, починены:

1. **У каждой эпохи вёрстки своя дата** (таблица в §1.2). Без неё все
   пары до 2007 года выходили `minor`.
2. **Вёрстка до 2007 — статья прямо в `<body>`**, без контейнеров. Шапка сайта
   (баннер архива, «how to cite», алфавит A–Z, плашка с датой) — всё, что выше
   `<h1>`; подвал — всё от последнего «Copyright ©». Раньше алфавит A|B|C
   приклеивался к первому абзацу и давал ложные правки.
3. **Благодарности (Acknowledgments)** в новой вёрстке лежат в `#acknowledgments`
   вне `#main-text`, в старой — после Related Entries. SEP правит их как minor
   («спасибо такому-то за найденную опечатку»). Теперь это часть текста.
4. **Minor бывает чистой правкой разметки**: `qualia` sum2008 → fall2008 —
   голый текст обернули в `<p>`, текст тот же. Ловится хешем разбиения на
   блоки (`struct_sha`). И наоборот: `logic-paraconsistent` fall1997 → win2000
   поменялись только ссылки, а SEP пометил substantive — дата решает.
5. **Эталон тоже ошибается.** `qualia` win1997 → win2002: archinfo говорит
   «без изменений», но текст реально другой (`('The` → `(The`), и дата в
   подвале сдвинулась с Nov 1 на Nov 2, 1997. Это не наш баг; такое
   расхождение на ранних изданиях надо просто показывать как есть.
6. **Логические символы до ~2012 — картинки**: `<img src="Box.gif">`,
   `ra.gif`, `models.gif`, `fishhook.gif`… (23 разных на трёх статьях).
   Экстрактор их молча терял: `□(A→B) → (□A→□B)` превращалось в
   `(AB) (AB)`, а переход SEP с GIF на Unicode (`logic-modal` win2003 → sum2005)
   выглядел как правка в 132 абзацах. Теперь известные картинки заменяются
   Unicode-символом (`SYMBOL_IMAGES`), прочие — меткой `[img:имя]`; та же пара
   даёт 2 блока (реальная правка `AxiomName → Axiom Name`). Вердикты
   классификатора эта ошибка не портила — только diff. После починки пары
   `minor` в статьях с формулами показывают 0–15 изменённых слов, контрольные
   пары — `markup_only`; MathJax (2016+) проблем не даёт.
7. **Покрытие считаем по символам, а не по словам.** По словам на
   `logic-modal` 2007–2016 выходило 87%: формула `(A→B)` с разметкой рвётся
   на куски. По символам — 100% везде.
8. **Обратная кавычка 1997 года** (`` `qualia' ``) — тоже типографика,
   нормализуется в апостроф.

### Известные ограничения (→ этап 3)

- Починка URL без смены текста ссылки не ловится: сравнивается только видимый
  текст `apparatus`.
- Related Entries — один `<p>` с разделителями `|`, так что +1 ссылка
  помечает изменённым весь блок. Надо резать по `|`.
- `mod`-блок показывается целиком. Для длинных абзацев нужна обрезка
  контекста внутри блока (±N слов вокруг правки).
- Правило «даты из разных форматов равны при разнице ≤ 1 дня» выведено на двух
  случаях. На большем эталоне может понадобиться уточнить.
- `SYMBOL_IMAGES` собран по трём статьям. Незнакомая картинка-символ даст
  метку `[img:имя]` — не потеря, но и не символ; при переходе на Unicode
  такая пара покажет ложную правку. В ядре — логировать незнакомые имена и
  пополнять словарь.
- Не проверены: статьи с рисунками и таблицами, переименованные статьи
  (редиректы слагов), статьи, удалённые из SEP.

## 14. Этап 1: ядро (2026-09-11)

Пакет `src/sepdiff/`, раскладка как в §2 (без `models.py` и `jobs.py`:
датаклассы живут рядом с кодом, очередь — этап 2):

| модуль | что делает |
|---|---|
| `config.py` | каталог данных (`./data` или `$SEPDIFF_DATA`), UA, crawl-delay |
| `db.py` | схема §3 + `user_version` для будущих миграций |
| `blobs.py` | content-addressed gzip-снимки |
| `fetcher.py` | httpx; 1 запрос / 5 с даже между запусками (время последнего запроса в `data/.last_request`); Retry-After и backoff на 429/5xx; fail-fast после 2 сетевых ошибок; отказ ходить в пути, закрытые robots.txt |

Решения, которых не было в плане:

- **Первое издание статьи ищется бинарным поиском.** Сначала последнее
  издание (заодно проверка slug), потом ~7 проб, потом всё от первого
  издания до последнего. Для статьи 2010 года это экономит ~50 запросов
  с 404, то есть ~4 минуты. Допущение: статья, раз появившись, из архива не
  пропадает; нарушение будет видно как `removed`.
- **Фетчер синхронный.** Для CLI async не нужен; веб-воркер этапа 2 будет
  звать `scan` в потоке — параллелить запросы к SEP всё равно нельзя.
- **`extract_version` в снимке.** Правка экстрактора — повысить константу, и
  снимки переизвлекаются из сохранённого HTML при следующем `log`/`diff`,
  без сети.
- **`sepdiff import`** — загрузить кеш спайка (`data/spike/`) без сети.
- **История показывает промежутки**: «N изданий без изменений» (скачаны,
  совпали) и «N изданий не скачано — не проверено» (частичное сканирование).
- **diff в терминале** — в стиле `git --word-diff`: `[-было-]{+стало+}`,
  длинный абзац обрезается до ±8 слов вокруг правки (закрывает одно из
  ограничений §13).

Тесты: `uv run pytest` — 80 проверок + 1 ожидаемый xfail (расхождение с
archinfo у `qualia`). Синтетические страницы трёх эпох вёрстки, фетчер на
`httpx.MockTransport` с фальшивыми часами, сервис на фальшивом сайте, CLI
через `CliRunner`, и регрессия на 36 парах настоящих снимков (если есть
локальный кеш).

Проверка вживую: `sepdiff fetch kant` через прокси — 62 запроса (7 проб
бинарного поиска + 55 изданий), ~6 минут, 65 снимков sum2010 — sum2026.
История **совпала с archinfo полностью**: все 9 ревизий (4 substantive,
5 minor, включая `fall2023` с правкой только в ссылках) и ни одной лишней —
остальные 56 изданий `markup_only`.

Не сделано в этапе 1 (→ дальше): двухфазное сканирование §4.2 (сейчас всегда
полное), живая версия `/entries/<slug>/`, HTML-вывод diff, `export-git`.
